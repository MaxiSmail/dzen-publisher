# Интеграция Базы Знаний Obsidian и Antigravity

Этот документ определяет структуру, метаданные и правила управления базой знаний Obsidian, с которой взаимодействует Antigravity.

---

## 📁 Структура хранилища (Vault)

- `📁 Projects/` — основные заметки по активным проектам.
- `📁 ADR/` (Architecture Decision Records) — логи архитектурных и технических решений.
- `📁 Daily/` — логи сессий общения, ежедневные отчеты и текущие контексты.
- `📁 Templates/` — шаблоны для создания новых файлов.
- `📁 Snippets/` — сниппеты кода и полезные конфигурации.

---

## 📄 Спецификация метаданных (Frontmatter Schema)

Каждая заметка в базе знаний должна содержать структурированный YAML-заголовок (Frontmatter):

```yaml
---
title: "Понятное название заметки"
type: conversation | decision | insight | project
status: seed | growing | evergreen | archived
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags:
  - topic/название-темы
  - project/имя-проекта
  - status/состояние
source: "session-id или URL источника"
summary: "Краткое резюме заметки в 1-2 предложениях"
related:
  - "[[СвязаннаяЗаметка1]]"
  - "[[СвязаннаяЗаметка2]]"
---
```

### Статусная модель:
1. `seed` — сырые мысли, быстрые заметки, логи свежих сессий.
2. `growing` — заметки, которые дополнялись или структурировались более одного раза.
3. `evergreen` — зрелые знания, проверенные паттерны и стабильные справочники.
4. `archived` — устаревшие решения или завершенные сессии, сохраненные для истории.

---

## 🏷️ Таксономия тегов
Теги должны использовать иерархическую структуру (через слэш `/`):
- `topic/` (например, `topic/python`, `topic/flutter`, `topic/networks`)
- `project/` (например, `project/arbat`, `project/shadows-war`)
- `source/` (например, `source/antigravity`, `source/user`)
- `decision/` (например, `decision/database`, `decision/ui-architecture`)
- `insight/` (например, `insight/performance`, `insight/bugfix`)
- `status/` (дублирует статус в тегах, например, `status/evergreen`)

---

## 📏 Правила работы и именования файлов

1. **Именование файлов:**
   - Для общих заметок: Kebab-case (например, `database-migration-guide.md`).
   - Для сессий общения (conversations): `YYYY-MM-DD-session-{project-name}-{timestamp}.md`.
2. **Обновление метаданных:**
   - При каждом изменении файла обязательно обновлять поле `updated`.
   - Не удалять старые заметки, если они стали неактуальны — менять статус на `status: archived`.
3. **Связывание (Cross-linking):**
   - Все новые заметки должны содержать как минимум 1-2 ссылки на существующие файлы в поле `related` или в тексте через синтаксис вики-ссылок `[[Имя заметки]]`.

## 🔧 Доступные Навыки (Skills)
Для управления базой знаний и автоматизацией используются кастомные навыки в папке `.agents/skills/`:
- `project-helper` — сохранение сниппетов кода и управление структурой проектов.
- `ui-ux-pro-max` — библиотека стилей, палитр, шрифтов и UX-гайдлайнов.
- `design-taste-frontend` — разработка чистых, нешаблонных фронтенд-интерфейсов.
- `doc-generation` — генерация отчетов PDF и презентаций PPTX.
- `obsidian-daily` — автоматическое управление ежедневными журналами Obsidian.
- `obsidian-markdown` — работа с вики-ссылками, сносками и плагинами Obsidian.
- `playwright-e2e-tests` — автоматическое сквозное тестирование интерфейсов.
- `tailored-resume-generator` — подгонка резюме под требования вакансий.

## 🔌 Доступные MCP Серверы (Model Context Protocol)
Для расширения возможностей в файле `%USERPROFILE%\.gemini\config\mcp_config.json` настроены серверы:
- `playwright` — автоматизация и рендеринг веб-страниц с помощью Playwright.
- `firecrawl` — глубокий парсинг и конвертация веб-страниц в чистый Markdown (настроен с активным API-ключом).
- `chrome-puppeteer` — управление браузером Chrome в headless режиме через Puppeteer.
- `markdown-processing` — сервер обработки и парсинга Markdown файлов (md-mcp).

## 📉 Локальный граф кодовой базы (Graphify)
Для быстрой ориентации в структуре проекта используется Graphify:
- **Папка вывода:** `graphify-out/` (всегда заносится в `.gitignore`).
- **Файлы:**
  - `graphify-out/graph.json` — сырой граф проекта (используется ИИ для точечных CLI-запросов).
  - `graphify-out/graph.html` — интерактивная визуализация связей для открытия в браузере.
  - `graphify-out/GRAPH_REPORT.md` — сводный текстовый отчет об архитектуре.
- **Интеграция с Obsidian:** При запуске `node .agents/scripts/extract_knowledge.js` отчет `GRAPH_REPORT.md` автоматически импортируется в Vault по пути `Obsidian/Projects/graphify_reports/{cleanProjectName}-report.md` с Frontmatter заголовками.
